# Методика и результаты тестирования

## Итоговые метрики (финальная версия)

Приложение на эмуляторе: AVD Pixel 8, Android 16 (API 36) arm64, 4 ядра, 6 ГБ RAM, Mac Apple Silicon.
Эмулятор медленнее современного телефона, поэтому RTF на устройстве ожидается ниже.

| Запись | Профиль | WER | Говорящие | Время / RTF |
|---|---|---|---|---|
| Диалог, 31 с, 2 голоса (`dialog_cats.wav`) | Подкаст | **5.8%** | **2 из 2**, 6/6 реплик | 7.1 с · **RTF 0.23** |
| Тот же диалог + шум 5 дБ и гул 50 Гц (`noisy.wav`) | Подкаст | 21.2% | 2 из 2 | ~0.5 |
| Русская речь с англицизмами, 18 с (`mixed.wav`) | Подкаст | 19.0% | 1 из 1 | ~0.5 |
| Песня, 2 мин, рэп с музыкой | Музыка | сходство с текстом **81.3%** | - | RTF ≈ 2.7 |
| Подкаст, 21 мин, 3 голоса, 204 реплики | Подкаст | - | **3 из 3, 91.0%** по времени | 8.2 мин · **RTF 0.39** |
| Презентация, 21 мин, 3 спикера по очереди | Презентация | - | **3 из 3, 100%** по времени, 42 реплики ≤ 35 с | 2 мин · **RTF 0.10** |

WER считается по словам без регистра и пунктуации; «3» против эталона «три» засчитывается
как ошибка. Отклонение начала реплик от эталона в диалоге: 20-110 мс.

### Диаризация на реальных голосах (калибровка)

LibriSpeech test-clean (40 реальных дикторов, CC BY 4.0): 12 разговоров по ~4 мин
на 2, 3, 4, 5, 7 и 10 говорящих (смена реплик, паузы 0.2-0.8 с). Метрика - доля времени
речи, отнесённая к правильному говорящему при оптимальном сопоставлении меток.

| Схема | Точность | Число говорящих точно | Скорость диаризации |
|---|---|---|---|
| ERes2NetV2, один порог 0.6 | 85.2% | 42% | RTF 0.40 |
| CAM++, один порог 0.7 | 87.1% | 67% | RTF 0.07 |
| **CAM++ (порог 0.5) + слияние по отпечаткам ERes2NetV2 ≥ 0.75 - итоговая** | **88.1%** | 54% | RTF ≈ 0.08 |

Почему итоговая схема двухступенчатая: одиночный порог, хорошо работающий на реальных
голосах, сливал два похожих голоса тестового диалога в одного (а в зашумлённом диалоге -
всегда). Низкий порог + слияние по чистым 20-секундным отпечаткам голоса держит раздельно
похожие голоса (сходство 0.55-0.69) и склеивает расщеплённого человека (0.9+).

## История оптимизаций

| Изменение | Было | Стало |
|---|---|---|
| Песни: отделение вокала UVR-MDX-NET-Voc_FT | 33.3% сходства | 81-83% |
| Длинные записи: склейка говорящих между блоками + cannot-link | 5 говорящих вместо 3, 72.8% | 3 из 3, 91.0% |
| Диаризация CAM++ вместо ERes2NetV2 + параллельно с ASR | подкаст 21 мин за 26 мин (RTF 1.22) | за 8.2 мин (RTF 0.39) |
| Диаризация до шумоподавления (DPDFNet сближал голоса 0.69 → 0.76) | шумный диалог: 1 говорящий | 2 говорящих |
| Отпечаток голоса не длиннее 20 с (реплики презентаций длятся минутами) | падение по памяти (> 3 ГБ на один отпечаток) | презентация обработана, 100% |
| Шумоподавление DPDFNet2 (на Mac, ошибок на `noisy.wav`) | 6 | 4 (GTCRN: 7 - отклонён) |

Отклонённые варианты (замерено): Qwen3-ASR-0.6B на песне 57.6% (против 81% у GigaAM + UVR),
Spleeter 50.5%, hotwords-бустинг англицизмов (искажал соседние слова), GTCRN.

## Юнит-тесты

`./gradlew :app:testDebugUnitTest` - 49 тестов: сборка слов из токенов, выравнивание слов и
говорящих, JSON-экспорт (формат ТЗ), ресемплер (в т.ч. потоковый = полный), шумодав/фильтр,
детектор музыки, нарезка UVR, связывание говорящих между блоками, сглаживание презентаций,
разрезание длинных реплик, нормализация англицизмов, промпты и защита LLM от изменения слов.

## Ограничения тестирования

Тестовые диалоги синтезированы TTS macOS (один голос, второй - со сдвигом высоты): это
жёсткий случай для диаризации, но лёгкий для ASR. Реальные голоса для диаризации проверены
на LibriSpeech (английская речь - отпечатки голоса от языка почти не зависят). Записей живой
русской речи с эталоном у нас не было: WER на них ожидается выше (10-20%).

Сырые результаты прогонов: `artifacts/test-results/results.csv`.
