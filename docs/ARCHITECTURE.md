# Архитектура решения

## Контекст

Задача: локально на Android превратить запись разговора в расшифровку с говорящими и
таймкодами, используя локальную LLM. Оценка: WER (40), диаризация (25), таймкоды (10),
скорость RTF (10), UX (10). Поэтому основные усилия вложены в качество ASR и диаризации,
а LLM подключена так, чтобы не ухудшать WER и не тормозить основной сценарий.

## Профили обработки

Пользователь выбирает профиль на главном экране; от него зависят модели и параметры.

| | Подкаст (по умолчанию) | Музыка | Презентация |
|---|---|---|---|
| Сценарий | разговор до 5 человек, 30 мин - 6 ч | песни, альбомы (импорт нескольких файлов) | спикеры по очереди, 2 - 8 ч |
| Подготовка звука | high-pass + адаптивный DPDFNet2 | отделение вокала UVR-MDX-NET-Voc_FT | high-pass + адаптивный DPDFNet2 |
| VAD | порог 0.45, куски ≤ 20 с | порог 0.6, куски ≤ 30 с | порог 0.45, куски ≤ 20 с |
| Диаризация | пауза внутри реплики 0.4 с | 0.5 с | 1.5 с + сглаживание: реплики < 3 с отдаются соседнему спикеру |
| Макс. говорящих | 5 (слияние самых похожих голосов) | 4 | 30 |
| Длина реплики | ≤ 60 с, разрез по концу предложения | ≤ 30 с | ≤ 30 с |
| Блок обработки | 10 мин | 2 мин | 10 мин |
| Протокол LLM | тема, тезисы участников, решения, задачи | о чём песня, образы, припев | тема, выступления по спикерам, выводы |

В профиле «Подкаст» начало записи проверяется детектором музыки: если это песня,
запись автоматически обрабатывается как в профиле «Музыка».

## Конвейер обработки длинных записей

```
аудиофайл(ы) / микрофон
   │  ProcessingEngine: очередь, по одной записи; ProcessingService держит процесс и CPU
   ▼
AudioSpooler: MediaCodec → потоковый windowed-sinc ресемплинг → PCM 16 кГц моно на диск
              (+ исходное стерео для отделения вокала); в памяти никогда нет всей записи
   ▼
BlockPlanner: блоки по 10 мин, разрез в самом тихом месте последних 10 с (слова не режутся)
   ▼  для каждого блока:
   ├─ песня? UVR-MDX-NET-Voc_FT, 44.1 кГц стерео, куски 5.9 с с кроссфейдом 1 с → вокал
   ├─ high-pass 80 Гц + нормализация; SNR < 20 дБ → DPDFNet2 (не для музыки)
   ├─ Silero VAD → GigaAM v3 RNNT (punct, beam search) → слова с абсолютным временем
   ├─ pyannote seg-3.0 + ERes2NetV2 → локальные говорящие блока
   └─ голосовой отпечаток каждого локального говорящего (до 20 с его речи)
   ▼
SpeakerLinker: локальные говорящие разных блоков связываются по косинусной близости
               отпечатков (тот же голос ≥ 0.9, разные ≤ 0.6, порог 0.7); затем самые
               похожие голоса сливаются до лимита профиля
   ▼
TurnSmoother (презентации) → TranscriptAligner: слово → говорящий с макс. перекрытием,
               реплика = слова одного говорящего; пауза > 2 с или длина > лимита → новая
   ▼
AnglicismNormalizer → (опц.) Qwen3-редактура пунктуации с проверкой «слова не изменились»
   ▼
история записей · экспорт JSON · протокол Qwen3 (для длинных записей map-reduce:
               до 8 частей → краткие выжимки → итоговый протокол)
```

Короткая запись (до 12.5 мин) - это один блок, поэтому тестовые диалоги обрабатываются
ровно так же, как раньше, без потерь на склейке.

Почему ASR и диаризация выполняются независимо, а затем объединяются по времени слов
(как в WhisperX): смена говорящего может произойти внутри одного фрагмента VAD,
и выравнивание по словам переносит границу реплики точно в место смены.

## Компоненты

| Пакет | Назначение |
|---|---|
| `engine/` | `ProcessingEngine` (очередь, модели, история, события), `ProcessingService` (foreground service + wake lock + уведомление с прогрессом) |
| `audio/` | потоковое декодирование, `StreamingResampler`, PCM-файлы на диске, запись с микрофона, `MusicDetector`, `VocalSeparator` |
| `asr/` | `Profile`, `SpeechPipeline` (блоки), `BlockPlanner`, `SpeakerLinker`, `TurnSmoother`, `WordBuilder`, `TranscriptAligner`, `AnglicismNormalizer` |
| `llm/` | JNI-мост к llama.cpp, промпты Qwen3 по профилям, map-reduce протокол, защита от изменения слов |
| `export/` | сериализация JSON строго по формату задания |
| `data/` | история (`recordings/<id>/audio, meta.json, transcript.json`), настройки, распаковка моделей |
| `ui/` | Compose: главный экран (профиль, большая кнопка, импорт), история, настройки |
| `cpp/` | `llama_jni.cpp` (Qwen3), `separation_jni.cpp` (UVR через C API sherpa-onnx, `dlopen`) |

## Основные технические решения

- **GigaAM v3 RNNT с пунктуацией**: одна из лучших открытых моделей для русского
  (заметно точнее Whisper на русском), сразу даёт регистр, знаки препинания и таймкоды токенов.
- **Блочная обработка**: 6 ч аудио - это 1.4 ГБ float в памяти и десятки ГБ на матрицу
  кластеризации диаризации. Звук спулится на диск в int16 (6 ч ≈ 700 МБ), обрабатывается
  блоками по 10 мин, а говорящие связываются между блоками по голосовым отпечаткам.
- **Foreground service** (`mediaProcessing` на Android 15+, `dataSync` ниже) + partial wake lock:
  многочасовая обработка не прерывается при выключенном экране; прогресс - в уведомлении.
- **Beam search (4 гипотезы)** вместо жадного декодирования: восстанавливает пропущенные слова
  ценой ~+35% ко времени ASR, таймкоды сохраняются.
- **Песни**: вокал отделяется UVR MDX-Net кусками по 5.9 с (на всей песне модель требовала
  > 6 ГБ). Сходство с текстом песни: 33% → 83%.
- **Шумоподавление DPDFNet2** включается адаптивно по оценке SNR; GTCRN проверен и отклонён.
- **Англицизмы**: словарь терминов с падежными окончаниями (hotwords-бустинг отклонён).
- **LLM Qwen3-1.7B (Q4_K_M)** без «размышлений» (`/no_think`), штраф за повторы.
- Нативные движки не потокобезопасны: каждый работает в своём однопоточном диспетчере.
- llama.cpp собирается из исходников (CMake, статически, `armv8.2-a+dotprod+fp16` для arm64).

- AndroidX, Jetpack Compose, Kotlin coroutines

## Безопасность и приватность

- В манифесте нет разрешения `INTERNET`, сетевой код отсутствует.
- Аудио читается через Storage Access Framework: приложение видит только выбранные файлы.
- Запись с микрофона только по явному нажатию, с запросом разрешения.
- `allowBackup=false`: расшифровки не уходят в облачные резервные копии.
