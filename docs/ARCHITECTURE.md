# Архитектура решения

## Контекст

Задача: локально на Android превратить запись разговора в расшифровку с говорящими и
таймкодами, используя локальную LLM. Оценка: WER (40), диаризация (25), таймкоды (10),
скорость RTF (10), UX (10). Поэтому основные усилия вложены в качество ASR и диаризации,
а LLM подключена так, чтобы не ухудшать WER и не тормозить основной сценарий.

## Конвейер обработки

```
аудиофайл / микрофон
   │  AudioDecoder: MediaExtractor+MediaCodec → mono → windowed-sinc ресемплинг 16 кГц
   ▼
нормализация громкости (тихие записи усиливаются до пика 0.9, не более ×10)
   │
   ├─► Silero VAD → фрагменты речи ≤ 20 с (+100 мс по краям)
   │       └─► GigaAM v3 RNNT (punct) → текст + время каждого токена
   │               └─► WordBuilder: токены → слова с абсолютным временем
   │
   └─► pyannote seg-3.0 + ERes2NetV2 + кластеризация → интервалы говорящих
                   │
                   ▼
          TranscriptAligner: каждое слово → говорящий с макс. перекрытием;
          подряд идущие слова одного говорящего → реплика; пауза > 2 с → новая реплика;
          speaker_N нумеруются по порядку появления
                   │
                   ▼
   (опц.) Qwen3: редактура пунктуации с проверкой «слова не изменились»
                   │
                   ▼
   UI (список реплик, плеер) · экспорт JSON · автосохранение · протокол заседания (Qwen3)
```

Почему ASR и диаризация выполняются независимо, а затем объединяются по времени слов
(как в WhisperX): смена говорящего может произойти внутри одного фрагмента VAD,
и выравнивание по словам переносит границу реплики точно в место смены.

## Компоненты

| Пакет | Назначение |
|---|---|
| `audio/` | декодирование любых форматов, ресемплер, запись с микрофона в WAV |
| `asr/` | конфигурация моделей, `SpeechPipeline` (VAD → ASR → диаризация), `WordBuilder`, `TranscriptAligner` |
| `llm/` | JNI-мост к llama.cpp, распаковка GGUF, промпты Qwen3, защита от изменения слов |
| `export/` | сериализация JSON строго по формату задания |
| `ui/` | Jetpack Compose, `MainViewModel` (единый `StateFlow<UiState>`) |
| `cpp/` | `llama_jni.cpp`: загрузка модели, greedy-генерация, UTF-8 вывод |

## Основные технические решения

- **GigaAM v3 RNNT с пунктуацией**: одна из лучших открытых моделей для русского
  (заметно точнее Whisper на русском), сразу даёт регистр и знаки препинания и таймкоды токенов.
- **sherpa-onnx 2.0.1** (готовый AAR): ONNX Runtime + VAD + диаризация в одной библиотеке,
  модели читаются напрямую из assets.
- **LLM Qwen3-1.7B (Q4_K_M, 1.1 ГБ)** в режиме без «размышлений» (`/no_think`), greedy-декодирование.
  Используется для протокола заседания и опциональной редактуры пунктуации.
  Редактура принимается, только если последовательность слов не изменилась (`WordGuard`),
  поэтому LLM не может испортить WER.
- Нативные движки не потокобезопасны: каждый работает в своём однопоточном диспетчере.
- llama.cpp собирается из исходников (CMake, статически, `armv8.2-a+dotprod+fp16` для arm64).

## Безопасность и приватность

- В манифесте нет разрешения `INTERNET`, сетевой код отсутствует.
- Аудио читается через Storage Access Framework: приложение видит только выбранный файл.
- Запись с микрофона только по явному нажатию, с запросом разрешения.
- `allowBackup=false`: расшифровки не уходят в облачные резервные копии.
