# Соответствие техническому заданию

Сверка с презентацией «Нейро-стенографист» (Nuclear IT Hack, ноябрь 2026).

## Обязательные требования (слайд 9)

| Требование | Реализация |
|---|---|
| Работает под Android | Android 8.0+ (API 26), arm64-v8a и x86_64, APK |
| Использует локальную LLM | Qwen3-1.7B (GGUF, llama.cpp через JNI) в APK: протокол записи, редактура пунктуации |
| Импортирует аудиозапись из памяти устройства | кнопка импорта, системный выбор файлов (wav, mp3, m4a, ogg, flac…), можно несколько файлов сразу |
| Преобразует речь в текст | GigaAM v3 RNNT с пунктуацией (sherpa-onnx) |
| Определяет и разделяет говорящих | pyannote segmentation 3.0 + 3D-Speaker ERes2NetV2, связывание говорящих между блоками |
| Формирует временные метки реплик | по таймкодам токенов ASR; `start_ms`/`end_ms` у каждой реплики |
| Отображает расшифровку | история записей → карточка: реплики, цвета говорящих, время, плеер |
| Экспортирует результат в файл | кнопка «Скачать JSON» + автокопия в `Android/data/ru.hexteam.stenographer/files/transcripts/` |

## Ограничения обработки (слайды 10-11)

| Ограничение | Как соблюдено |
|---|---|
| Не передавать аудио внешним сервисам | в манифесте нет разрешения `INTERNET`, сетевого кода нет |
| Не использовать облачные API | все модели выполняются на устройстве (ONNX Runtime, llama.cpp) |
| Не вычислять на сервере/компьютере | вся обработка в процессе приложения |
| Не подменять работу модели готовой расшифровкой | в APK нет расшифровок; результат строится из аудио |
| Работа без интернета, модели на устройстве к моменту проверки | все модели внутри APK (assets), при первом запуске распаковываются локально |

## Ввод и вывод (слайды 14-15)

- Вход: файл из локального хранилища **или** запись из интерфейса приложения (большая кнопка).
- Выход: JSON строго по формату:

```json
{ "transcript": [ { "speaker_id": "speaker_1", "start_ms": 1250, "end_ms": 4380, "text": "Добрый день!" } ] }
```

`speaker_id` - строка `speaker_N`, `start_ms`/`end_ms` - целые миллисекунды, `text` - строка.
Формат проверяется юнит-тестом `TranscriptJsonTest`.

## Порядок проверки (слайд 16)

1. Установить APK → 2. импортировать запись (профиль по умолчанию «Подкаст» подходит для
диалогов) → 3. транскрибация и диаризация запускаются автоматически → 4. «Скачать JSON» в
карточке истории → 5-6. сравнение с эталоном (WER, RTF). Время обработки и RTF показываются
в карточке записи.

## Уровни решения (слайды 17-19)

| Пункт | Статус |
|---|---|
| Базовый уровень целиком | ✅ |
| Предварительная обработка аудиосигнала | ✅ high-pass 80 Гц, нормализация громкости |
| Фильтрация пауз и неречевых фрагментов | ✅ Silero VAD |
| Устойчивое определение участников при смене реплик | ✅ выравнивание слов по говорящим, связывание между блоками; 88.1% на 2-10 реальных голосах |
| Восстановление пунктуации | ✅ GigaAM v3 punct + опциональная LLM-редактура |
| Отображение прогресса обработки | ✅ по этапам и блокам, на экране и в уведомлении |
| Воспроизведение аудио с переходом к реплике | ✅ нажатие на реплику |
| Обработка фонового шума и некачественных записей | ✅ адаптивный DPDFNet2 |
| Распознавание коротких реплик и перебиваний | ⚠️ частично: выравнивание по словам, minDurationOn 0.2 с |
| Одновременная речь нескольких участников | ⚠️ частично: слово получает говорящего с наибольшим перекрытием |
| Устойчивость к тембру и манере речи | ✅ ERes2NetV2, связывание по отпечаткам голоса |
| Оптимизация использования оперативной памяти | ✅ потоковое декодирование, блоки, куски для UVR |
| Ускорение инференса за счёт аппаратных возможностей | ⚠️ ARM dotprod/fp16 в llama.cpp, int8 ONNX; NPU/GPU не используются |
| Редактирование и повторная обработка фрагментов | ✅ правка текста и говорящего, повторное распознавание фрагмента реплики |
